BEELZEBUB 1.x → 2.0

Modernize the runtime. Keep the task model.

Beelzebub 2.0 moves to Node 24+, strict TypeScript, standard decorators, and modern ESM and CommonJS entry points. Use this checklist to make the breaking changes deliberately.

Minimum runtime Node 24.15+ ESM + CommonJS · npm 12 for contributors

WHAT CHANGED

A focused breaking release.

The public task concepts remain familiar, but the infrastructure beneath them has been replaced. Plan this as a runtime migration, not a routine dependency update.

01 Node 24.15+

Update local development, containers, and every CI runner first.

02 Dual modules

Use native ESM or keep the callable CommonJS API.

03 Standard decorators

Usage stays familiar; custom legacy decorator implementations change.

STEP 1

Upgrade Node and choose your module format.

Use Node.js 24.15 or newer. Existing CommonJS projects can keep require('beelzebub'); ESM projects get native default and named imports. Both entry points share the same callable facade.

tasks.js 
const bz = require('beelzebub');
// ESM equivalent: import bz from 'beelzebub';

class BuildTasks extends bz.Tasks {
  build() {
    return compile();
  }
}

bz.add(BuildTasks);
void bz.run('BuildTasks.build');
STEP 2

Update the changed entry points.

1.x 2.0
require('beelzebub') require('beelzebub') or native import
Shared global instance bz facade or bz.create(config)
Beelzebub.cli() bz binary or new BzCLI().run()
Babel-built CommonJS ESM + CommonJS with shipped declarations

Tests that use the singleton can call bz.delete() between cases. Independent applications can use bz.create(config).

STEP 3

Move custom decorators to the standard API.

Built-in @defaultTask, @help, and @vars syntax remains the same. Do not enable experimentalDecorators. Rewrite custom decorators from the legacy descriptor signature to (value, context).

TypeScript configuration 
{
  "compilerOptions": {
    "target": "ES2024",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "strict": true,
    "verbatimModuleSyntax": true
  }
}
STEP 4

Prefer native async control flow.

Promises, async functions, generators, and Node streams remain supported. New work should use async/await; generator tasks continue to run for compatibility.

build.ts
- *build() {
-   yield compile();
- }
+ async build() {
+   await compile();
+ }
STEP 5

Load TypeScript task files explicitly.

JavaScript task files load through native import(). For task files that contain TypeScript syntax or decorators, install tsx in the consuming project and register it with Node.

$ node --import tsx ./node_modules/beelzebub/dist/bin/beelzebub.js --file ./beelzebub.ts BuildTasks.build

SHIP IT SAFELY

Migration checklist.

  1. Upgrade local Node, containers, and CI runners to Node 24.15 or newer.
  2. Keep CommonJS or adopt ESM, then use the matching package entry point.
  3. Update custom decorators to the TC39 standard decorator API.
  4. Replace calls to the removed Beelzebub.cli() helper.
  5. Configure a TypeScript loader or compile TypeScript CLI task files.
  6. Run existing tasks and compare hook, variable, stream, and CLI behavior.
